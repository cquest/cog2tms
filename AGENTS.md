# cog2tms — "COG → TMS tiles" service in Python

COG URL in, **EPSG:3857 XYZ (OSM) tiles** out; pixels are fetched from the remote
COG by **HTTP byte-range requests only** (never the whole file).
**Language convention: all code, comments, docstrings, tests, commit messages and
docs are in English** — exception: `README_fr.md` is a maintained French mirror of
`README.md`; edit the two together, never let them drift.
Code style: **minimal, idiomatic, no over-engineering**.

## API contract

```
GET /                                    web UI: map preview
GET /static/…                            UI assets (vendored maplibre-gl, maplibre_app.js)
GET /c2t/{z}/{x}/{y}?u=<cog url>         tile: format=png|jpeg|webp|auto, quality, size
                                         (512 by default, 128..1024 multiple of 16),
                                         bidx, rescale, blackmax
GET /c2t/{z}/{x}/{y}.geojson?u=…         COG footprint ring (debug)
GET /c2t.tms.json?u=…                    TileJSON (bbox, minzoom/maxzoom; the tile
                                         template pins size=256 to match its zoom
                                         math; plus a "cog" provenance block —
                                         codec name, whole size, Last-Modified —
                                         all already known from the open)
GET /healthz
GET /robots.txt                          "User-agent: * Disallow: /c2t" + X-Robots-Tag
                                         (nofollow, noimageindex) on every response
GET /openapi.json                        OpenAPI 3.1, generated by FastAPI and cached;
                                         /docs and /redoc serve it (their HTML loads
                                         swagger-ui / redoc from a public CDN)
```

Every GET route also answers **HEAD** (health checks and `curl -I` must not see
405), as a transport detail rather than a declared method — FastAPI's `@app.get()`
is GET-only where a bare Starlette `Route` would have added HEAD. The pure-ASGI
`_HeadAsGet` (`main.py`) rewrites `scope["method"]` to GET — a copy of the scope,
so uvicorn's access log keeps saying HEAD — and swallows the response body while
keeping the `Content-Length` the GET would have declared. Dropping the body is
ours: h11 does it, uvicorn's httptools path (the default of `uvicorn[standard]`,
so the Docker image) writes the whole tile after a HEAD's headers, which
desynchronises a keep-alive connection. Same handler, same tile-cache key. Declaring
HEAD on the routes instead would document a HEAD twin per operation with a
duplicate `operationId`. A bare `OPTIONS` is a conformant `405` + `Allow`, honest
about HEAD (`_honest_allow`); only a CORS preflight is answered (`allow_methods`:
GET, HEAD).

The schema describes the real contract — tile 200 as `image/png|jpeg|webp`, the
400/404/502 bodies through `_err`/`_ERRORS`, every query parameter documented,
the web UI hidden with `include_in_schema=False` — with **no FastAPI validation**
(`Literal`, `ge`/`le`, `pattern`): it would turn the pinned `400`s into `422`s.

Errors: `400` (zoom/x/y outside matrix, format, size, URL/scheme, bidx/rescale/
blackmax, signed/wide/float data without `rescale`, unsupported CRS, redirect
chain refused or looping), `404` (unreachable COG, not a GeoTIFF, rotated
raster, unreadable samples), `502` (upstream error).

## Locked decisions

| Topic | Decision |
|---|---|
| Engine | Pure-Python COG reader over **curl_cffi** byte-range (libcurl: HTTP/1.1 and HTTP/2 by ALPN, `HTTP2=0` pins 1.1; bodies bounded by a write callback); images with Pillow+numpy; JPEG-in-TIFF blocks decoded by **simplejpeg** (identical pixels, releases the GIL) with a Pillow fallback; warp/resample by **`cv2.remap`** (opencv-python-headless — the one heavy wheel, accepted for the render win). Small surface, prebuilt wheels only, full control of what is fetched — exception accepted: **pyproj**, regular dependency — the PROJ fallback for EPSG codes outside the pure-Python table; the table always takes precedence. |
| Y orientation | **OSM-style XYZ** (Y points down). Pass-through, no flip. A unit test pins the convention. |
| Out-of-bounds tiles | **200 + empty tile**: fully transparent PNG/WebP (alpha=0); JPEG has no alpha → solid fill, configurable `EMPTY_TILE_BG` (default `0,0,0`). |
| Output formats | **PNG, JPEG, WebP** + `format=auto` = the `Accept` header only: webp iff `image/webp` (q>0) is listed explicitly, else png; the source codec (JPEG-in-TIFF) plays **no** role. **Wildcards (`image/*`, `*/*`) never select webp** — JOSM and plain clients send them and cannot decode it. WebP = Pillow `exact=True` (without it, RGB is blended to a background where alpha<255) + `method=0`; `WEBP_LOSSLESS=1` → lossless+exact = bit-identical to PNG. The resolved format is part of the tile-cache key. PNG stays the default when `format` is omitted. |
| Size limit | **No 413 based on Content-Length** (multi-GB COGs are legitimate): validation via magic bytes `II*`/`MM*` + `MAX_ZOOM`. |
| Default tile size | **512 px** (`size` accepted 128..1024 but only as a **multiple of 16** — jpeg macroblock / TIFF block grid — off-grid is a `400`). Measured against the four 256 children one zoom deeper (same on-screen GSD, jpeg q80, headers counted): always lower client volume — −5 % at z13 to −37 % at z19 on COG_SMALL — and ≈4× fewer upstream bytes (the children re-fetch the boundary blocks; empty children pay 4× the header+fill overhead). TileJSON answers pin `size=256` because its minzoom/maxzoom assume a 256 px grid. |

Stack: Python 3.12, FastAPI + uvicorn, curl_cffi (Range reads, h2 by ALPN),
numpy, Pillow, simplejpeg, imagecodecs, opencv-python-headless; dev: pytest,
pytest-cov, httpx.

## Supported COG features (`app/geotiff.py`)

- Classic TIFF + BigTIFF; tiled layout, planar contig, no rotation.
- Compressions: None, Deflate (+predictor 2), LZW, PackBits, **ZSTD (50000)**,
  **WEBP (50001)** — each block is one whole RIFF/WEBP image, padded to the
  full tile at edges like JPEG; 8-bit RGB/RGBA only (else refused at open),
  straight (never premultiplied) alpha, decoded by imagecodecs/libwebp with a
  Pillow fallback — pixels identical to GDAL/libwebp,
  **JPEG XL (50002, DNG 1.7 spells the same codestream 52546)** — each block is
  one standalone bare JXL codestream: no container, and unlike JPEG no tables
  to splice; gray/RGB/RGBA in uint8/uint16/float32 (GDAL's codec set, else
  refused at open), decoded by imagecodecs/libjxl (no Pillow fallback); the
  codestream's shape and sample type are checked against the level,
  **old-style JPEG**: blocks may lack their tables — GDAL moves the DQT to the IFD
  `JPEGTables` tag 347 (`SOI` + DQT + `FF7F`/`FFD9`/nothing; the DHT stay per
  block, they differ block by block) → splice tag (minus trailing EOI) + block
  body, then simplejpeg (`colorspace="RGB"`,
  `"GRAY"` for 1-sample levels; Pillow fallback). LZW/PackBits go through
  **imagecodecs** when installed (it also reads the libtiff LZW variant our
  pure-Python decoder rejects); ZSTD requires imagecodecs — blocks are one plain
  frame or libtiff big-endian size-prefixed segments (`_zstd_decode`).
- Internal overviews (`NewSubfileType & 1`) — linked IFD chain **or SubIFDs**
  (tag 330, what `cog_merger` writes); **1-bit internal masks** (`& 4`) →
  `valid` mask; merger union holes: `TileByteCounts` entries of 0 are never
  fetched and stay no-coverage (transparent, not a black smear).
- GeoTIFF tags: ModelTiepoint/PixelScale (a ModelTransformation — rotated/skewed
  raster — is refused at open), GeoKeyDirectory(+DoubleParams), GDAL_NODATA
  (nodata only when **every** band matches, GDAL parity; compared **without**
  casting the declared value into the sample type, which numpy 2 refuses:
  `-9999` on unsigned samples or NaN on integer ones match nothing instead of
  raising, and a NaN nodata needs `isnan` — `==` never finds it),
  ExtraSamples→alpha.
- Sample format (tag 339): unsigned / signed / float, dtype from the
  **(BitsPerSample, SampleFormat)** pair (`_DT`, 8/16/32/64-bit ints + float32/64).
  Refused at open: mixed per-band formats, predictor 3 (float byte shuffle),
  predictor 2 on non-integer samples (cumsum is modular, done in the sample
  dtype), complex (4) / float16 / bps 12-24 / an unparsable `GDAL_NODATA` — the
  old `_DT.get(bps, "u1")` fallback read bps 12 as 8-bit and rendered wrong
  pixels in silence.
- CRS subset (`app/crs.py`, pure Python): 4326, 3857, 2154 (Lambert-93),
  CC42–CC48 (3942–3948), UTM 326xx/327xx, user-defined LCC/TM from the
  projection keys (3075 = CT 1/8/9/27, both GDAL and ESRI key spellings):
  Snyder series, forward and inverse; < 1 cm and < 1 mm vs PROJ golden values
  (the inverse matches PROJ `+approx`, same series family, to ≤ 0.05 mas);
  anything else → **optional** PROJ fallback first, else 400. The fallback
  (`_proj_fallback`) speaks for PROJ's whole EPSG registry
  — projected and geographic codes, datum shifts included (EPSG:2056 is its
  case: CH1903+ oblique Mercator, ~1 m off if approximated as LCC). The table
  always wins — in-table codes stay deterministic whatever pyproj does — and
  without the wheel the 400 is unchanged. With it, accuracy is the embedded
  PROJ's: proj.db ships in the wheel, national grids (NADCON, Japanese) do
  not, so those datums get PROJ's grid-less transformation.

## Warp pipeline (`app/tiles.py`)

Overview level chosen so the source window ≥ **tile px** — never resample up
(the old tile/2 rule halved zoomed-out sharpness, −1.5× gradient energy, for a
~4× smaller window: not worth it); the window is **not clamped to the raster** —
`_window` pads outside pixels with zeros + `valid=False` so tiles straddling
the COG edge go transparent instead of smearing the last row/column → blocks
read via `reader.read_many` (adjacent ranges merged within `MERGE_GAP`, groups
fetched in parallel) → decode inline, or in the shared `_POOL` when the window
is ≥ 1 Mpx **and** the codec releases the GIL → per-pixel source coords (exact
affine if the source is 3857, else **17×17 inverse-projection control grid**
bilinearly interpolated) → bilinear resample by `cv2.remap` of premultiplied
`data*valid` + `valid`, both with `BORDER_CONSTANT`, then divided: out-of-
window/out-of-footprint samples contribute 0 to both, so invalid pixels divide
to exactly 0 — no clamp, no branch (sampling coordinates count source **pixel
centers**, `ox/oy` are GeoTIFF corners: the grids carry a `- 0.5`, without it
every tile was corner-sampled and low-passed even at 1:1) → Gaussian **unsharp
mask** on overview tiles (`_sharpen`, `SHARPEN=0.3`, never at level 0,
halo-guarded to pixels whose 3×3 neighborhood is fully valid; all-C mask ops,
≈0.2 ms — numpy needs 6× more for the same filter) → encode PNG/JPEG/WebP
(`main._encode`).
`cv2.setNumThreads(1)` at import: internal threading gains nothing at 256² and
would oversubscribe across uvicorn workers.

## Performance levers (headline numbers in the README table)

- **Bulk head prefetch** (`HEAD_PREFETCH`): one 64 KB `Range:` read absorbs all
  IFD/tag parsing; IFDs at EOF get one chunk around the IFD pointer instead.
- `TileOffsets`/`TileByteCounts` **lazy**: small arrays load once per level, big
  ones per window as a row-major contiguous slice (`_Level.index`).
- One `read_many` batch per IFD; window blocks in parallel groups, or one
  **multi-range GET** (`multipart/byteranges`) — rejection remembered per host.
- **Transport = curl_cffi**: one curl handle per thread (`_session`, handles are
  not thread-safe) fed by one **process-wide range pool** (`_ranges`, 8 workers)
  so those handles/connections stay warm across renders; h2 by ALPN (`HTTP2=0`
  pins 1.1). Bodies are read by curl's write callback into a list (≈4.5 ms per
  256 KB range, vs 12 ms if streamed through a queue) — the same callback is the
  byte cap, and the header callback supplies the status of an aborted transfer.
- **Encoded-tile LRU** (`TILE_CACHE`) + per-key `asyncio.Lock` single-flight.
- **Head spans from sqlite after a restart** (`HEAD_CACHE`): opening a COG we
  already met before the process went down costs zero GETs — the 64 KB head
  zone and the IFD zone near EOF come from disk, pixels/IFDs re-parsed from
  those bytes; coherence is untouched (the row re-anchors `If-Range`).
- **Block decode in `_POOL`** (`DECODE_THREADS`, gated by `_PAR_MIN_PX` = 1 Mpx):
  only GIL-free codecs go there (simplejpeg, zlib, imagecodecs LZW and WebP —
  libwebp releases the GIL, ≈0.3–0.9 ms/128² block, only a handful per tile);
  Pillow (JPEG/WebP fallback), imagecodecs PackBits (9 µs) and ZSTD (53 µs)
  stay inline but are fast enough.
- **Warp = `cv2.remap`** of premultiplied `data*valid` + `valid` + renorm
  (≈1.4–2 ms per 256² tile vs 16–18 ms for the numpy gather; a dependency-free
  numpy rewrite only reaches ≈11 ms — this is why the opencv wheel is kept).

## Cache coherence (COG replaced under the same URL)

- `httprange._versions`: `url -> (ETag|Last-Modified, total size)` anchored from
  the first 206/HEAD and kept across reader reopens.
- Later single-range GETs carry `If-Range` (direct hosts only, never on multi-
  range GETs): a replaced file makes the server answer `200 + whole file` →
  `CogChanged`, recognized **from the response headers** (curl's header callback
  fires before any body byte) and cut off by the body cap — that answer is never
  buffered; for servers that ignore `If-Range`, ETag/size drift between
  responses also raises `CogChanged`.
- Cached tiles are revalidated by one 1-byte `If-Range` GET at most every
  `VALIDATE_TTL` s; probe failures are ignored — cached bytes keep being served
  (stale-while-error).
- On `CogChanged`: `_purge(url)` = `pool.invalidate` + `httprange.forget` + drop
  every tile-cache key starting with `url|`, then re-render once; two consecutive
  render failures → 503.
- Behind a redirect, `If-Range`/ETag anchoring is **skipped** (`_direct` false):
  one host's validators must never be presented to another (alternating mirrors
  would loop `CogChanged` → 503). Size drift is still checked and the probe
  re-walks the chain. Not caught: in-place replacement behind a stable target
  with identical total size.
- **Across restarts** (`HEAD_CACHE`, `app/headcache.py`): each `prefetch` span
  (head zone, IFD zone near EOF) is saved to sqlite **with its validator** —
  and only when responses carried a change detector (ETag/Last-Modified, direct
  host). Reopening with no in-memory anchor adopts the span, seeds `_versions`
  + `_checked` + `_size` from the row: the first single-range read already
  carries `If-Range`, so a file replaced while the process was down is caught
  by the very first block fetch (200 → `CogChanged` → `_purge` → rows dropped)
  — stale head bytes are never mixed with a new file's blocks. An entry that
  now redirects also raises `CogChanged` before settling (`_cold` guard: the
  saved spans belonged to the old direct answer). No validator → nothing is
  ever written. Rows are bounded (4096 most recent, 30-day TTL — a flood of
  distinct urls cannot grow the disk) and a corrupt/unwritable database is a
  cache miss, never an outage.

## Redirects answered by the remote server

- `httprange._follow` walks 30x itself (`allow_redirects=False` everywhere,
  `MAX_REDIRECTS`=5, loop detection): every `Location` is resolved with `urljoin`
  and passed through `check_url` **before** connecting — a remote server cannot
  send us to a private/reserved host or outside `ALLOWED_HOSTS`; refusal/loop/
  hop-limit → `CogRedirect` → 400, the refused host is never contacted.
- One walk per reader, not per range: reads go straight to the settled host
  (`_target`); the 404/403 negative cache stays keyed by the requested URL;
  a 3xx body is closed unread.

## Tests

### Unit (offline, default: `pytest`)

Fixtures written **in pure Python by conftest** (tiled TIFF + internal 2×
overview + GeoTIFF tags): EPSG:4326 and EPSG:3857 COGs with identical content,
JPEG-in-TIFF — also stored the GDAL way, DQT moved to the IFD `JPEGTables` tag
347 (blob ending `FF7F`/`FFD9`/nothing, blocks keeping their own DQT, and a blob
without SOI) — single-band JPEG, LZW (both dialects)/PackBits/ZSTD/predictor-2,
lossless + lossy **WebP** blocks (RGB, RGBA+alpha, single-band refused),
lossless + lossy **JPEG XL** blocks (RGB, RGBA+alpha, gray, 2-sample refused,
DNG id 52546),
16-bit single band, GDAL_NODATA, ExtraSamples alpha, 1-bit internal mask,
ModelTransformation, unsupported CRS, an EPSG:2056 fixture + its EPSG:3857 twin
(PROJ fallback, geokeys 2048:4150 + 3072:2056), SubIFD-published overviews (empty chain),
count-0 merger-hole blocks (bogus past-EOF offsets), **SampleFormat** fixtures
(int8/int16 with a `-9999` sentinel written over the first column, float32 with
a NaN sentinel, an out-of-range `GDAL_NODATA`, and the refusals: bps 12, complex
samples, predictor 3, predictor 2 on floats, `GDAL_NODATA="N/A"`), a non-TIFF
file — served by a local Range-capable HTTP server that counts bytes. Pinned
behaviors (do not break):

- center tile PNG; **default tile size 512** (the no-`size` endpoint returns
  512×512, an on-grid `size=144` still overrides, an off-grid `size` is a 400);
  **XYZ convention** (a northern-half red
  square lands in the tile's upper half); **reprojection parity** 4326 vs 3857
  (MSE < 100);
- **edge tiles**: transparent >2 tile-px outside the footprint (both CRS paths),
  never clamped edge values;
- **blackmax**: split exact (`max|band| ≤ blackmax` → transparent, `>` kept),
  colors untouched; out-of-bounds → transparent PNG / solid JPEG;
- **webp + auto**: lossy webp pixels within 48 of the png reference (saturated
  fixture colors are webp's worst case); lossless+exact bit-identical to png
  (with blackmax alpha); empty webp tile transparent; the Accept matrix (browser,
  JOSM wildcards, `q=0`, garbage, none) yields webp only on an explicit
  `image/webp;q>0` — the source codec never interferes; cache keyed by the
  resolved format;
- 400 paths (zoom, x/y, format, scheme, bidx, rescale, blackmax), 404 missing
  COG / non-TIFF / rotated raster / unreadable samples, `size`/`bidx`,
  TileJSON/GeoJSON/healthz — TileJSON carries the `cog` block (codec name from tag
  259, whole size, `last_modified` **omitted** when the host sends no validator;
  the versioned test server proves the Last-Modified is kept apart from the ETag
  and re-anchored after a purge+reopen); the same open-error matrix on `.geojson` and
  `.tms.json`; web UI (`GET /` = map preview page + vendored assets, the dropped
  `/maplibre` route answers 404);
- **HEAD = GET without the body** on every route (`/healthz`, `robots.txt`,
  `/static/…`, TileJSON, geojson, tiles): 200, an **empty body** (stripped by our
  middleware, since uvicorn's httptools path would not strip it), `content-length`
  equal to the GET payload, identical `content-type`/`Cache-Control`/`X-Robots-Tag`,
  and a GET right after a HEAD fetches **no** upstream byte (the HEAD paid for the
  render and shares the tile-cache key). A bare `OPTIONS` → 405 whose `Allow`
  contains GET and HEAD; a CORS preflight → 200 with
  `access-control-allow-methods: GET, HEAD`;
- **OpenAPI document is client-generable**: regenerated (`app.openapi_schema =
  None`) with **no** `Duplicate Operation ID` warning, unique `operationId`s, tile
  200 = the three image types, 400/404/502 documented, `tags: ["tiles"]`, all 7
